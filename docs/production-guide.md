# 制作规范 v0.2

更新：2026-11-03。适用于“不会物理的忆白”的热统与量子力学系列。

## 制作顺序

核心问题 → 科学核验与完整脚本 → 关键片段原型 → 配音定稿 → 按实际音频制作动画与字幕 → 审片 → 交付。

允许用原型探索解释方式，但不要在旁白仍有内容缺口时锁死整片时长。原型时间轴是参考；最终配音决定节奏。

## 角色与交接

- 用户：确定选题与表达偏好，选择外部 AI 配音软件，审听并提供最终音频。
- 制作：资料整理、模型计算、脚本分镜、代码动画、音画对齐、验证与导出。
- 语音优先逐段交付，保留独立音轨；音乐在后期混音，保留来源与许可记录。
- 不为达到固定分钟数重复讲解或机械延长停留；长视频保留完整解释链，短视频另做叙事与画幅。

## 分阶段交付与完成条件

| 阶段 | 交付 | 完成条件 |
| --- | --- | --- |
| 选题 | 一页选题卡 | 一个核心问题、一个核心收获，明确不讨论什么 |
| 研究 | 论点—来源表、计算记录 | 定义、假设、适用条件、数值与边界可追溯 |
| 脚本 | 完整旁白、分镜 | 新概念先解释；结尾回应开头；关键解释缺口已处理 |
| 原型 | 最难的 30–60 秒片段 | 画面能承担推理，颜色、字幕与构图可读 |
| 配音 | 原始音频、读音表、段落编号 | 无漏句和关键错读，音色和语速已审听 |
| 生产 | 动画、时间轴、字幕 | 关键动作与实际旁白对应；数据和绘图含义一致 |
| 审片 | 科学、表达、技术检查记录 | 缺陷已修正或明确标记，不能用自动检查替代听看 |
| 交付 | MP4、SRT、文案、来源、版本记录 | 文件能实际播放和下载，成片与源码版本对应 |

## 固定表达与视觉规范

- 账号：不会物理的忆白。
- 介绍语：我是忆白，让我们把这个问题，变成一个看得见的实验。
- 结束语：我是忆白，和你一起，让理解发生。
- 深色背景，克制用色；颜色之外辅以标签、线型或形状。
- 每次移动、变色和投影对应明确含义；先建立问题，再引入公式。
- 同一个对象保持同一种颜色；字幕与公式分区。
- 区分真实空间、态空间、概率分布，以及微观状态、宏观量、单次轨迹与统计平均。
- 区分示意动画、数值模拟、实验；枚举顺序不能冒充物理时间。
- 图轴缩放、归一方式和必要科学边界保留在观众画面中。
- 制作状态、内部复听备注、技术调试信息放在制作记录中，不进入正式片。

## 科学与数值核查

保存参考来源支持的具体论点和适用条件。记录模型、参数、单位、初始条件、算法、随机种子与依赖版本；仅填写实际适用的项。

按模型选择守恒量、解析结果、归一化、枚举唯一性、已知极限等检查。需要时检查步长、采样与精度；不为静态排版重复编写无意义测试。

平衡分布与趋近平衡的动力学分别验证。模型假设不能写成不需要条件的普遍结论。

## 源码与时间轴

每期建议保留 references/、script/、data/、scenes/、audio/、timeline/、renders/、release/。

模型计算与渲染分开，旁白与画面分开。动画采用确定性的 render(t) 思路；使用同一份结构化时间轴生成字幕和交接文本。此处是接口约定，当前尚未交付统一渲染框架。

时间单位为秒，段落使用稳定 ID。记录 source_start/source_end 与 target_start/target_end，避免覆盖旧时间轴后失去重排依据。换版时更新章节跳转。

源码不得依赖未打包的上期文件或临时绝对路径。需记录安装和运行命令；完成一次独立目录重建检查后，才能称为可复现。

## 配音与同步

1. 先核对台本，再生成配音；每段约 10–30 秒，按语义调整。
2. 记录术语、希腊字母、数字读法；不要把导演备注放进配音文本。
3. 整体固定偏移可平移；累计或分段错位必须逐段重排。
4. 优先调整画面，不为追赶旧时间轴强制加速人声。
5. 识别时间戳仅辅助定位。缺词、低置信度句首或音乐干扰段必须复听；推断位置要标明。
6. 烧录字幕需随画面同步调整；独立 SRT 也要更新。
7. 背景音乐压低至不遮挡旁白，片尾按实际需要淡出；保留原始音频和混音版本。

## 输出、验收与发布

首期使用 HTML Canvas、Chromium、FFmpeg；它们是已验证路径，不限制后续改用其他代码动画工具。

通用输出优先 MP4 / H.264 / yuv420p / 固定 30 fps / AAC，并启用 faststart。选择与分辨率相容的编码档位；1080p 导出不代表低分辨率素材获得了原生细节。

验证顺序：媒体参数 → 全片解码 → 实际播放与跳转 → 实际下载并核对文件 → 电脑与手机审片。没有做过的设备验收写“未验证”。

主交付是标准视频文件，网页预览作为辅助。站点部署成功不能证明用户端播放成功；播放器本地测试也不能证明线上权限与资源加载正确。

故障先分层：整页不可达 / 媒体加载 / 解码 / 播放交互 / 下载。收集实际报错后修复，不反复换链接当作已解决。内置视频、Blob 或备用地址只能作为兼容措施，不能代替诊断。

B 站横屏与抖音竖屏分别设计。发布包含封面、标题简介、标签、置顶评论、来源与所需署名。官方音色、音乐的使用条件以采用时的条款为准。

上传或发布用户提供的素材前确认目标及授权；已获授权的同一目的地不重复询问。私有预览保持私有，不把文件放入公开仓库作为下载捷径。

## 版本与归档

Git 保存源码、小型配置、脚本、计算与制作记录；大视频、原始音频、模型权重采用独立存储，不直接进入内容仓库。

每个交付版本记录：版本号、源码提交、媒体文件名、时长、分辨率、音轨版本、字幕版本、校验摘要、验证范围和已知问题。内部复听记录不能因从观众页面删除而丢失。
